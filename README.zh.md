# Veilmi

> 在送出訊息之前，先將它加密。

[English README](README.md)

Veilmi 是一款免費且開源的應用程式，讓使用者可以在透過既有的通訊平台傳送文字之前，先在自己的裝置上進行本機加密。

與其完全依賴通訊服務替你保護原始訊息，Veilmi 讓你先在自己的裝置上將文字加密。

```text
你的訊息
   ↓
 Veilmi
   ↓
加密文字
   ↓
LINE / Messenger / WhatsApp / 電子郵件 / 其他通訊管道
   ↓
加密文字
   ↓
 Veilmi
   ↓
原始訊息
````

通訊平台負責傳送加密後的文字，而明文內容則由 Veilmi 在使用者的裝置上進行處理。

## 為什麼我會開發 Veilmi

家人、朋友，以及我們所信任的人之間的私人對話，應該屬於正在進行這些對話的人。

我們每天都會透過大型通訊平台與其他人聯絡。有些服務已經提供很強的加密保護，而另一些服務則可能因功能或設定方式不同，而提供不同程度的保護。

我不希望自己對話內容的隱私，完全取決於負責傳送訊息的平台。

Veilmi 背後的想法很簡單：

> **在把訊息交給通訊平台之前，先由自己保護它。**

Veilmi 並不是用來取代通訊軟體，而是一個可以與它們一起使用的小工具。

使用者先透過其他方式約定一組共用密碼，在自己的裝置上將文字加密，再把加密後的訊息複製到自己選擇的任何通訊管道中。

Veilmi 保護的是**訊息內容**，但它不會隱藏例如以下資訊：

* 誰正在與誰通訊；
* 訊息在什麼時間傳送；
* 人們通訊的頻率。

Veilmi 也無法保護已經遭到入侵的手機，也不能讓一組強度不足的共用密碼自動變得安全。

它的目的只是讓使用者對自己的**對話內容**多一層控制。

## 目前使用的密碼學技術

Veilmi1 目前使用：

* AES-256-GCM 進行具驗證功能的加密；
* PBKDF2-HMAC-SHA256 進行基於密碼的金鑰衍生；
* 隨機產生的 salt 與 nonce；
* 帶有版本資訊的加密訊息封裝格式；
* 可選擇不同 PBKDF2 工作量的保護等級。

相關技術細節與設計理由，都記錄在上面的文件中。

Veilmi 仍在開發中，而且**尚未經過獨立的專業安全稽核（security audit）**。

請不要把 Veilmi 視為一個已經通過正式安全稽核的資安產品。

## 如何回報問題

1. 在 GitHub 開啟這個 repository。
2. 點選 repository 上方的 **Issues**。
3. 點選 **New issue**。
4. 為問題寫一個簡短而清楚的標題。
5. 描述你發現的問題。
6. 點選 **Submit new issue**。

一份有幫助的問題報告可以包括：

* 你原本預期會發生什麼；
* 實際發生了什麼；
* 造成問題的操作步驟；
* 如果相關，你使用的手機型號及 Android / iOS 版本；
* 如果有的話，附上截圖或錯誤訊息。

例如：

```text
標題：

輸入訊息後 Decrypt 按鈕仍然無法使用

描述：

輸入加密訊息及共用密碼後，
我原本預期 Decrypt 按鈕應該可以使用。

步驟：

1. 開啟 Veilmi。
2. 切換到 Decrypt。
3. 貼上加密訊息。
4. 輸入共用密碼。

結果：

按鈕仍然維持無法使用的狀態。

裝置：

Android 14
```
