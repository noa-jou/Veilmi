# Veilmi

> 在送出訊息以前，先由自己把它加密。

[English README](README.md)

Veilmi 是一個免費且開放原始碼的 App，讓使用者在把文字交給現有的通訊平台以前，先在自己的裝置上完成加密。

與其完全依賴通訊服務替我們保護原始訊息，Veilmi 希望讓使用者先在自己的裝置上把文字加密，再把加密後的內容交給通訊平台傳送。

```text
你的訊息
   ↓
 Veilmi
   ↓
加密文字
   ↓
LINE / Messenger / WhatsApp / Email / 其他管道
   ↓
加密文字
   ↓
 Veilmi
   ↓
原始訊息
```

通訊平台負責傳送加密後的文字，而原始文字則由 Veilmi 在本機處理。

---

## 為什麼我開發 Veilmi

家人、朋友，以及彼此信任的人之間的私人對話，應該屬於正在進行這段對話的人。

我們每天都會使用大型通訊平台。有些服務本身已經提供完善的端對端加密，而不同平台、功能和設定之間的保護程度也可能有所不同。

但我不希望自己對話內容的隱私，完全取決於負責傳送它的平台。

Veilmi 背後的想法很簡單：

> **在把訊息交給通訊平台之前，先由自己保護它。**

Veilmi 並不是要取代 LINE、Messenger、WhatsApp、Email 或其他通訊工具。

它是一個可以配合現有通訊方式使用的小工具。

雙方先透過其他方式約定共享密碼，在自己的裝置上加密文字，再把產生的加密訊息貼到任何想使用的通訊管道。

也就是說，通訊平台收到的是加密後的文字，而不是原本想說的內容。

Veilmi 並不能隱藏誰和誰正在通訊、通訊時間、頻率等資訊，也不能保護已經被入侵的手機，更不能把一個容易猜到的密碼變成強密碼。

它的目的，是讓使用者對自己的訊息內容多掌握一層控制權，而不是把所有保護責任都交給通訊平台。

## 加密設計

Veilmi 的安全性並不依賴隱藏原始碼或加密方式。

這是一個 open-source 專案，希望它的設計可以被閱讀、質疑、測試和改善。

如果你想了解 Veilmi 目前是怎麼完成加密和解密的，可以從這裡開始：

- [`docs/crypto-notes.md`](docs/crypto-notes.md) — 以較容易理解的方式介紹目前的加密與解密流程。
- [`docs/crypto-design-and-future.md`](docs/crypto-design-and-future.md) — 說明目前加密技術的選擇依據、相關標準與安全指引、限制，以及未來可能改善的方向。

其他開發、測試與設計相關文件可以在 [`docs/`](docs/) 資料夾找到。

## 目前使用的加密技術

Veilmi1 目前使用：

- AES-256-GCM authenticated encryption
- PBKDF2-HMAC-SHA256 密鑰派生
- 隨機 salt 與 nonce
- 有版本編號的加密訊息格式
- 可選擇的 PBKDF2 保護等級

詳細規格與設計理由請參考上面的技術文件。

Veilmi 目前仍在開發中，而且**尚未接受獨立的專業資安審核**。

因此請不要把目前版本視為已經通過正式安全驗證的資安產品。

## 如何告訴我問題

1. 打開 Veilmi 的 GitHub repository。
2. 點選頁面上方的 **Issues**。
3. 點選 **New issue**。
4. 寫一個簡短而清楚的標題。
5. 描述你發現的問題。
6. 點選 **Submit new issue**。

如果可以的話，一份有幫助的回報可以包含：

- 你原本預期會發生什麼；
- 實際發生了什麼；
- 如何重現這個問題；
- 如果相關，你使用的手機型號和 Android/iOS 版本；
- 截圖或錯誤訊息。

例如：

```text
標題：
輸入訊息後，Decrypt 按鈕仍然不能使用

內容：
我原本預期輸入加密訊息和共享密碼後，
Decrypt 按鈕會變成可以按。

重現步驟：
1. 打開 Veilmi。
2. 切換到 Decrypt。
3. 貼上加密訊息。
4. 輸入共享密碼。

結果：
按鈕仍然不能使用。

裝置：
Android 14
```
